# VV-SR 结构性复盘（EXP-0025 → EXP-0054）

> **性质**：复盘，不是新实验。全部结论来自 `docs/specs/vv.md` §13–§33、`docs/agent/ledger.jsonl`、
> 源码与 `docs/agent/evidence/` 里已有的原始日志；**没有新增采集**，也没有开 IDA。
> 本文回答一个问题：这两天 30 个实验的失败，是不是同一处结构缺陷的不同截面。

## 0. 结论

> **系统一直用「能观测到的形状」（尺寸 / 格式 / 创建顺序 / 视口 / draw 次数）代替「定义角色的边」，
> 而唯一稳定给出角色的边——TAAU draw 内部的材质绑定——恰好被「替换」这个动作切断了。**

由此派生三笔债，分别对应三种症状：

| 债 | 机制 | 症状 |
|---|---|---|
| 身份 | 角色靠形状猜，回退路径必然先撞到更新的、非本帧使用的面 | 冻结 / 黑面 / 显示尺寸面 / 裁剪 |
| 自指 | suppress draw → 材质不再绑定 → 不知道该读哪张 → 回退猜面 | resize 后无法重捕（EXP-0053/0054） |
| 层错位 | 在后缓冲上覆盖，等于把引擎的**显示变换**一起替换，然后自己复刻它 | 偏暗 / 偏亮 / 饱和 / 白点不收敛 |

## 3. 五个结构性根因

### R1｜身份用形状猜，不用边

`pickInputs()` = 「fmt26 + 尺寸≈渲染尺寸 → 取清单里最新的一张」；清单顺序是 RTV **创建顺序**。
bgfx 的 transient 池是复用的，「最新创建」描述的是池的分配历史，不是「本帧谁写了它」。
证据：EXP-0026 的 15 个 fmt26 候选里，选中的那张几乎不动；EXP-0038/0045 的语义面都落在
`colour[2]`，而回退会取 `colour[0]`（比它更新、不是本帧世界色）。

### R2｜替换与观测同源

角色只在 draw 里解析（declarator 阶段的 dep 是 `{w,h,fmt}` 附件描述，没有资源）；
资源只在材质绑定里出现；而材质 hook 的守卫是「原 draw 正在跑」。
一 suppress，语义资源不再更新；resize 清空之后只能回退猜面。
EXP-0054 的 4 帧有界转发是对这个循环的局部破环，代价是替换变成时分复用。

### R3｜替换发生在「高了一层」

引擎有显示分辨率的 HDR 中间面（`2560×1440 fmt26`，双缓冲），TAAU 的输出目标是它（依赖名 `Color0`）；
之后还有一条「显示尺寸 + DSV + 1 draw」的 list 把 8bit 后缓冲写出来（48-list 世界帧的 list 44）。
**2026-10-28 更正**：EXP-0055 证明 44 写的是另一张 RTV、不是 `Color0`；arg10 的写者是 25
（无 DSV、单 draw），见 §4.4。44 与 `Color0` 的读写关系仍未证。
我们在**它之后**覆盖后缓冲，等于把 TAAU 与显示变换一起替换，然后自己复刻曝光/色调/编码。
详见 [ADR 0005](../decisions/0005-vv-r3-write-arg10.md)。

### R4｜时序状态没有「生产者事件」

DLSS history 与白点 IIR 的失效条件只有 `frameNo<=2` / `world` 变 / `renderGeneration` 变 / `view` 变；
缺的是「颜色指针/角色换了」「这一帧 TAAU 真的跑了（recapture/missed）」「输入是空的」。
EXP-0053 的 `targetRing=[2.72,−7.93,2.72,−8.01]` 就是交替输入下的一阶平滑轨迹；
`(2.72−7.97)/2 → 2^−2.63 ≈ 0.16` 与实测 `White=0.1527` 一致。

### R5｜没有契约级 oracle

B1c 是唯一一次建了客观 oracle（切点 capture + 离线曲线拟合），一次答掉「插在哪、颜色域」。
之后大多回到「人眼看」，于是「症状被接受为机制」：竖缝消失 → MVLowRes 被接受，但 MV 的 Y 符号
被搁置；白点让画面回来 → 白点被保留。

## 4. 关键新证据（本轮复核）

### 4.1 同一指针跨 8800×（EXP-0045 三批，同一次运行）

```
sr_semantic_1_p1C1E2174710  rgb_mean = 0.131628   ← 正常
sr_semantic_2_p1C1E2174710  rgb_mean = 0.002354   ← 极暗
sr_semantic_3_p1C1E2174710  rgb_mean = 20.734270  ← 极亮
```

同一个 `ID3D12Resource`、几秒之内（runbook 是「暗态与 F11 亮态各采一批」）、`prev_same=1`。
⇒ **输入域/曝光是真的会变**，不是「选错面」能解释的；引擎自己的 F2 在该状态仍是正常亮度
（EXP-0046 记录了 0.629083），说明下游存在一级归一化。
⇒ 这否定了「曝光是幻影」的说法：**H1（选错面，0053 的黑面）与 H2（真实域变化，0045 的亮暗）
是两件不同的事，被同一个白点机制吸收成了同一种症状。**

### 4.2 显示分辨率上同时存在两种格式

日志里 `2560×1440 fmt=26 flags=0x1`（R11G11B10，仅 RT）与 `2560×1440 fmt=28`（RGBA8）并存；
交换链不可能是 R11G11B10，所以 26 是渲染目标。EXP-0032 从 declarator 的 arg10 链解析出的两个
native 指针，与日志里那两张 2560×1440 fmt26 逐位相同，且逐帧交替（双缓冲）。

### 4.3 帧形（48-list 世界帧）

```
25: v2560x1440      d1 x6     ← 无 DSV
27..40: 844x475 → 26x14       ← bloom 链
44: v2560x1440 z    d1 x6     ← B1c 的 tail-4（唯一改变整块后缓冲的 pass）
45: v2560x1440 z    d61 x6    ← HUD
```

B1c 在 tail 8…5 的切点图是「上一帧内容（含我们自己的面板）」——如果 25 写后缓冲，
这些切点应看到本帧世界。⇒ **25 不写后缓冲**；44 是后缓冲写者。
因此「TAAU 直接写后缓冲」的旧结论（`vv.md` §5.1）大概率是错的。

### 4.4 2026-10-28 更正（EXP-0055）：arg10 的写者是「无 DSV 的前置 list」，不是 44

EXP-0055 在 declarator 之后解析 arg10（依赖名 **`Color0`**）的 native，并把每个 list 首次
`OMSetRenderTargets` 的 RTV 反查成 `ID3D12Resource*`，在同一次提交里做指针相等比较。7 个连续帧：

- arg10 native 在两个地址间交替（双缓冲），候选 RTV 全部 resolved；
- 命中始终是**显示分辨率、无 DSV、单次 6-index draw** 的前置 list（随帧形 49/47/84）；
- 后续带 DSV 的合成 list（68/66/103）用的是**另一张 RTV**，从未与 arg10 相等。

⇒ 48-list 帧里 **25 写 `Color0`，44 写另一张资源**；44 不是 arg10 的写入者，也**没有被证明**直接
采样 arg10（中间还隔着 bloom/后处理）。
⇒ 旧说法「44 是读 arg10 的显示变换」作废；R3 的切点应改为**arg10 写入 list 之后立刻**，
而不是「44 之前」。`via=pre-hud`（44 之前）覆盖的是合成后的后缓冲，不是 TAAU 的输出。
⇒ 同时也说明：`Color0` 是离屏显示尺寸颜色，不是交换链后缓冲。

证据：`docs/agent/evidence/arg10-list-binding-EXP-0055.log`（agent2 线产出，已拷入本仓库）。

## 6. 方法层面的两条

1. **未知项按症状切，不按机制切**：`U-taau-skip-colour-freshness` 3 次、`U-adaptive-whitepoint` 3 次、
   `U-mv-*` 4 次，各自合格，合起来没回答「这个 pass 的契约是什么」。建议把契约写成一张
   **pass 契约表**（角色 / 生产者 / 消费者 / 格式 / 域 / 状态 / 时序），填不满的行才是未知项。
2. **症状被接受为机制**：任何「修好某个可见症状」的改动都要附带机制级断言，否则只记「现象改变」。
