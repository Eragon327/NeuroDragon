# 0002. 不做对驱动内核的逆向 patch（`.trpk` / INT8 / MFG）

- **状态**：已采纳（2026-10-24）
- **相关**：[specs/nr.md](../specs/nr.md)、[specs/trp.md](../specs/trp.md)、
  [roadmap.md](../roadmap.md) §4.4

## 背景

TRP 为了让 NR 在 RTX 20/30/40 上跑，自带 `.trpk` 内核包；它还实现了 INT8 量化版本，
并在菜单里提供 MFG（多帧生成）乘数解锁。这些都不是 NGX 的公开调用面，而是**逆向并 patch
`nvngx` 内核**得到的。

本项目在 Windows 客户端里注入 DLL，已经有崩溃隔离、签名漂移、驱动兼容这些风险；
如果再叠加「改写驱动侧内核」，风险不再是线性增加。

## 决策

**只使用 NGX 的公开接口**（`NVSDK_NGX_D3D12_*` + `DLSSNR.*` / `DLSS.*` 参数键），
不做 `.trpk`、INT8、MFG 解锁这类逆向 patch。

## 理由

1. **法律与稳定性风险**：patch 驱动侧内核依赖对 NVIDIA 二进制的逆向，分发与使用都不在正常
   SDK 许可范围内；一旦驱动更新，patch 目标消失或偏移，表现为随机崩溃（没有可诊断的返回码）。
2. **本机平台不需要 `.trpk`**：`.trpk` 只服务 RTX 20/30/40；**50 系（本机 RTX 5070 Laptop）
   用原始 kernel**（TRP `CHANGELOG.md` 0.4.4）。为 20/30/40 做内核包，对当前目标平台是纯成本。
3. **INT8 收益不成立**：NR 的主要成本是网络推理本身，INT8 换来的收益与「输入缩放 / 隔帧」
   这些公开手段重叠，而后者可回退、可测量。
4. **MFG 不是我们的能力**：帧生成本身还没开工（阶段 3），解锁乘数属于纯实验，不可能成为产品功能。

## 后果

- 打包只带 `nvngx_dlssnr_310.9.16.dll`（266 MB），不带 165 MB 的 legacy 310.8、不带 310 MB 的 int8，
  也不带任何 `.trpk`。
- 上家包 `E:\V12\MO2\mods\DLSS5+6倍帧生成` 里的 INI 是**默认值**（`Provider=0`、`XeFGMultiplier=2`），
  所谓「6 倍帧生成」不在包里，是 TRP 菜单里的乘数 + MFG 解锁——与我们无关。
- 用户若自行使用第三方内核包，不属于本项目的支持范围。
- 这条决策**不因排期变化而改变**：阶段 3 加入 FG 也不代表会去做 MFG 解锁。
